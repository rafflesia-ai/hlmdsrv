# MDsrv Headless v0 Contract

`hlmdsrv` v0 is a headless trajectory/session tool. The stable unit is a dataset or job manifest plus machine-readable CLI/HTTP reports; GUI state and renderer details remain optional companions.

## Stable Core

These surfaces are intended to be safe for automation in v0:

- CLI identity and diagnostics: `version --json`, `doctor --json`, `capabilities --json`, `gromacs doctor --json`, `store doctor --json`.
- Store lifecycle: `init`, `ingest`, `validate`, `list datasets`, `probe`, `dataset inspect`, `dataset update`, `dataset rename`, `dataset delete`, and `dataset gc`.
- Job manifests: `schema job`, `schema manifest`, `schema batch`, `schema openapi`, `init job`, `explain`, `run --plan`, `run --dry-run`, `run --report`, and JSONL `batch`.
- Frame access: `frames count`, `frames get`, `frames extract`, `/datasets/{id}/frames/count`, `/frames/{frame}`, `/frames/range`, and the compact `MDSF` binary payload.
- Selections: `selection save`, `selection list`, `selection resolve`, `selection export-index`, `selection delete`, and HTTP selection CRUD.
- Indexing and static streaming: `index build`, `index show`, `index chunks`, `/frames/index`, `/frames/chunks`, and chunk encodings `json`, `bin`, and `bin-zstd`.
- Core analyses: `distance`, `angle`, `dihedral`, `rmsd`, `rgyr`, `rmsf`, `contacts`, `sasa`, and `hbonds` where the selected backend supports them.
- Publishing and archives: `session publish`, `session list`, `publish static --verify`, `pack`, `unpack`, and `.mdsrvx` archives.
- Server mode: `/health`, `/version`, `/capabilities`, `/metrics`, dataset routes, session routes, read-only mode, auth-token checks, request ids, resource limits, and structured error responses.
- Jobs: `jobs submit`, `jobs status`, `jobs wait`, `jobs logs`, `jobs events`, `jobs retry`, `jobs cancel`, `jobs stats`, `jobs prune`, `/jobs`, `/jobs/{id}`, `/jobs/{id}/events`, and `/jobs/metrics`.
- Debugging and fixtures: `serve smoke`, `debug bundle`, `quickstart`, `self-test`, `fixtures list`, `fixtures mdanalysis-adk`, and `bench`.

## Stable JSON Shapes

Stable JSON responses keep these top-level conventions:

- Success reports include an `ok` boolean when they are pass/fail diagnostics.
- Failures use `error`, `code`, and, for HTTP, `request_id`.
- Versions use `contract` or explicit schema fields such as `version: "mdsrv.job/v1"` or store metadata `version: "mdsrv.store/v1"`.
- Backend reports distinguish `gromacs`, `python`, `mdtraj`, and `mdanalysis` availability and include a remediation `hint` when a backend is missing.
- Job events use `type: "mdsrv.job_event/v1"`, stable `event` names, `job_id`, `status`, and timestamps.
- Reports that write files include paths, byte counts, SHA-256 digests where available, warnings, and per-step timings.

Golden examples live under `internal/mdsrvcli/testdata/contracts/` and are verified by:

```sh
npm run test:mdsrv:contracts
```

## Archive Contract

`.mdsrvx` is a ZIP bundle with `index.yaml` at the root. v0 archives may contain:

- dataset manifests under `datasets/`
- topology files under `topology/`
- trajectory files under `trajectory/`
- frame indexes under `indexes/`
- materialized chunks under `chunks/`
- traces under `traces/`
- Mol* and MVS companions under `visualization/`
- session files under `session/`
- catalog files such as `trajectory_index.json`, `session_index.json`, and `store.json`

`unpack` rejects path escapes, restores required store metadata and directories, and initializes missing empty catalogs when older archives do not contain them.

## Stable Operational Profiles

The default Docker image includes GROMACS, Python, and `mdtraj`. It is the recommended runtime smoke target. The full image is selected with:

```sh
docker build --build-arg MDSRV_PYTHON_BACKENDS=full -t headlessmolstar:local-full .
```

The full profile adds `MDAnalysis` and `MDAnalysisTests` so `fixtures mdanalysis-adk` and `npm run dogfood:mdsrv:real` can exercise a real public trajectory without committing binary fixtures to the repository.

Release and dogfood gates are:

```sh
npm run test:release
npm run docker:verify
npm run docker:verify:full
npm run dogfood:mdsrv
npm run dogfood:mdsrv:real
npm run test:linux-clean
```

## Experimental Surface

These remain intentionally less frozen in v0:

- exact numerical behavior for advanced analyses across different backends
- full cross-dialect selection translation between atom-index, mdtraj, MDAnalysis, and Mol*/MVS selectors
- full MVS visualization semantics generated by `visualize`
- multi-tenant auth, quotas, object storage, CDN manifests, signed URLs, and static-server deployment policy
- live simulation streaming and external worker backends
- compatibility migration from older NGL MDsrv scripts and arbitrary Mol* `.molj` states

The contract rule is: automation should depend on the stable commands, JSON envelopes, archive layout, and error codes above; advanced backend behavior can improve without a v0-breaking change when the command and report shape stay compatible.
